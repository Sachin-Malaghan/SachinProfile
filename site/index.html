Flagship project · Unreal Engine 5 · C++

AstroVerse

A solar system simulator at true physical scale. You can fly to any planet, land and walk on it, launch a real rocket from a real pad, and watch the Sun cross the sky over your own city.

Flyby: Earth, Moon, Mars, Jupiter
Mission mode: SLS and Gaganyaan launches

Casual space apps squash distances to make everything fit on screen. AstroVerse keeps size and distance on one scale, so the Sun really does look tiny from Neptune. Making that work takes engineering in every layer.

  • PhysicsFull N-body gravity, double precision, symplectic leapfrog integrator so orbits don't drift at high time-warp
  • ScaleFloating origin and scaled-space rendering, with a separate galaxy domain and a smooth hand-off between them
  • Real dataNASA LRO, MGS MOLA and NOAA ETOPO elevation; JPL Horizons orbits; IAU rotation models
  • RenderingCustom HLSL for atmospheres, rings and the solar corona; exposure metered from the real sunlight
  • MissionsData-driven launch vehicles, gravity-turn ascent, staging, then hand-flown docking with Odyssey, a 340 m spinning ring station-ship modelled in Blender
  • PerformanceSeparate desktop, VR and mobile budgets; profiled per render pass with profilegpu
  • Architecture10 C++ modules in four strict layers, with automated tests run headless

Structural analysis · 3D editor

ArchEngine

A desktop editor for designing buildings and checking them with finite element analysis. I rebuilt it from a Qt/QML front end to a lighter ImGui editor on a four-layer plugin core, without touching the existing solver DLLs.

  • FEM solver with stress heat-map view and safety factors
  • 8 hot-loaded plugin DLLs with API version checks
  • Scripting layer with 25+ APIs, used live in a REPL or headless in CI
  • Export to DXF, SVG, PDF and IFC (BIM)
  • Result<T> error handling, type-safe handles, per-frame linear allocator

Game engine · built from scratch

RiftCore

A modular C++ game engine where every system is its own DLL, loaded at runtime with no hard dependencies between modules. It is the foundation the ArchEngine redesign was based on.

  • Entity-component system with component pools
  • Job system: thread pool with 19 workers and ParallelFor
  • OpenGL 4.6 renderer: Blinn-Phong lighting, OBJ/MTL loading, textures
  • Editor with selection, transform gizmos and live stats
  • CMake presets, stable 60 fps on a Quadro M4000
